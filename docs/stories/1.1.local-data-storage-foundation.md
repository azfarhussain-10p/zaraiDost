# Story 1.1: Local Data Storage Foundation

## Status
Draft

## Story
**As a** farmer with intermittent connectivity,
**I want** the app to store my farm data locally on my device,
**so that** I can access my information even without internet.

## Acceptance Criteria
1. AC1: App uses SQLite for local data persistence on mobile devices
2. AC2: Initial app installation requires <100MB storage space
3. AC3: Core farm data (crops, field info, previous queries) stored locally
4. AC4: App functions without internet for viewing historical data
5. AC5: Data schema supports offline storage for all core entities

### Data Model Requirements

**Core Entities for Offline Storage** (derived from Epic 1 and architecture):
1. **Farmers**: User profile information
   - Fields: id, name, location, phone, language_preference, organic_preference, created_at, updated_at
2. **Fields**: Farm land parcels
   - Fields: id, farmer_id (FK), name, size_acres, soil_type, location_gps, created_at, updated_at
3. **Crops**: Crops planted in fields
   - Fields: id, field_id (FK), crop_type, planting_date, expected_harvest_date, status, created_at, updated_at
4. **Queries**: Historical user queries and AI responses
   - Fields: id, farmer_id (FK), query_text, response_text, timestamp, query_type (health/irrigation/market/climate), sync_status
5. **Images**: Crop images for health analysis
   - Fields: id, crop_id (FK), local_file_path, remote_url, analysis_result_json, confidence_score, timestamp, sync_status

**Schema Considerations**:
- All tables need `created_at` and `updated_at` timestamps for sync logic
- `sync_status` field tracks: 'pending', 'synced', 'conflict'
- Foreign key constraints to maintain referential integrity
- Indexes on timestamp and foreign key columns for query performance

### Storage Management Strategy

[Source: prd/epic-1-offline-first-intelligence.md - Story 1.1]
- Target: <100MB total app storage
- SQLite database should be <20MB initially
- Implement cleanup policies:
  - Queries older than 90 days archived or deleted
  - Image cache limited to 50 most recent images
  - Automatic cleanup when approaching 100MB limit

### Security Considerations

[Source: architecture/architectural-principles-and-best-practices.md]
- Encryption at rest for sensitive farmer data (consider SQLCipher)
- Encryption in transit for sync operations (HTTPS/TLS)
- GDPR/PDPA compliance: user data deletion support required
- JWT authentication for backend sync operations

[Source: architecture/non-functional-specifications.md]

- App startup time should not increase significantly with offline data
- Efficient indexing on frequently accessed tables
