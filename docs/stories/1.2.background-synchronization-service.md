# Story 1.2: Background Synchronization Service

## Status
In Progress

## Story
**As a** farmer who occasionally has internet access,
**I want** my local data to automatically sync with the cloud when I'm online,
**so that** my data is backed up and accessible from other devices.

## Acceptance Criteria
1. AC1: Background service detects internet connectivity changes
2. AC2: Automatic sync triggers when connection is available
3. AC3: Sync handles conflicts with server-side data (last-write-wins strategy)
4. AC4: User can manually trigger sync from settings
5. AC5: Sync status visible to user (syncing, synced, pending)
6. AC6: Failed syncs retry with exponential backoff

### Technical Implementation Details

**Network Detection**
- Use `@react-native-community/netinfo` for connectivity monitoring
- Track connection type: WiFi, cellular (4G/3G), none
- Consider WiFi-only sync option for data usage concerns

**GraphQL Sync API Endpoints** (Backend requirements)
Backend team should provide these mutations:
```graphql
mutation SyncFarmer($input: FarmerInput!) { syncFarmer(input: $input) { id, updated_at } }
mutation SyncField($input: FieldInput!) { syncField(input: $input) { id, updated_at } }
mutation SyncCrop($input: CropInput!) { syncCrop(input: $input) { id, updated_at } }
mutation SyncQuery($input: QueryInput!) { syncQuery(input: $input) { id, updated_at } }
mutation SyncImage($input: ImageInput!) { syncImage(input: $input) { id, remote_url, updated_at } }
mutation BatchSync($entities: [EntityInput!]!) { batchSync(entities: $entities) { results } }
```

**Conflict Resolution Strategy**
- Compare `updated_at` timestamps between local and remote records
- Last-write-wins: Most recent timestamp takes precedence
- Update local record with server data if server timestamp is newer
- Update remote with local data if local timestamp is newer
- Log all conflicts with entity type, local timestamp, remote timestamp

**Exponential Backoff Configuration**
- Initial retry: 1 second
- Subsequent retries: double previous delay (2s, 4s, 8s, 16s, 32s)
- Maximum delay: 60 seconds
- Maximum retry attempts: 6 (total ~127 seconds before giving up)
- Reset retry counter on successful sync

**Background Sync**
- Use `react-native-background-fetch` for iOS/Android background tasks
- Configure minimum interval: 15 minutes (platform constraints)
- Battery-conscious: skip sync if battery <20%
- WiFi-only option for background sync

### Data Model Updates

No new tables required. Update existing sync_status field usage:
- **'pending'**: Local changes not yet synced
- **'synced'**: Successfully synchronized with server
- **'conflict'**: Conflict detected and resolved (for logging)
- **'failed'**: Sync failed after max retries

Add sync_metadata table (optional for enhanced monitoring):
```sql
CREATE TABLE sync_metadata (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  entity_type TEXT NOT NULL,        -- 'farmer', 'field', 'crop', 'query', 'image'
  entity_id INTEGER NOT NULL,
  sync_attempt_count INTEGER DEFAULT 0,
  last_sync_attempt DATETIME,
  last_sync_success DATETIME,
  last_error_message TEXT,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```
