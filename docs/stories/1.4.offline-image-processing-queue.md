# Story 1.4: Offline Image Processing Queue

## Status
Draft

## Story
**As a** farmer capturing crop images in the field,
**I want** images to be analyzed locally and queued for upload,
**so that** I don't have to wait for internet to get initial results.

## Acceptance Criteria
1. AC1: Images stored locally with metadata (timestamp, location, crop type)
2. AC2: On-device AI processing completes within 5 seconds
3. AC3: Images automatically upload when connectivity restored
4. AC4: Upload queue prioritizes recent/unsynced images
5. AC5: User can view pending uploads and their sync status
6. AC6: Storage management prevents filling device (max 50 images in queue)

### Technical Implementation Details

**Image Capture and Storage**
- Use `react-native-image-picker` or `expo-image-picker` for camera access
- Save images to app's document directory (iOS) or files directory (Android)
- File naming convention: `crop_image_{timestamp}_{unique_id}.jpg`
- Image compression: Reduce quality to 80% to save storage
- GPS location extraction using `react-native-geolocation-service`

**Metadata Extraction**
```javascript
// Image metadata structure
{
  id: "uuid-v4",
  crop_id: "reference to crops table",
  local_file_path: "/path/to/image.jpg",
  remote_url: null,  // Set after S3 upload
  timestamp: "2025-10-22T10:30:00Z",
  location_gps: {
    latitude: 31.5204,
    longitude: 74.3587,
    accuracy: 10
  },
  crop_type: "wheat",  // User-selected or inferred
  file_size_bytes: 2457600,
  analysis_result_json: {
    disease: "Wheat Leaf Rust",
    confidence: 0.89,
    recommendations: ["Apply fungicide", "Remove affected plants"]
  },
  confidence_score: 0.89,
  sync_status: "pending",  // pending, synced, failed
  upload_attempts: 0,
  created_at: "2025-10-22T10:30:00Z",
  updated_at: "2025-10-22T10:30:05Z"
}
```

**On-Device Processing Pipeline**
1. Capture image via camera
2. Save raw image to local file system
3. Extract GPS coordinates and timestamp
4. Preprocess image for model input (Story 1.3 ImagePreprocessor)
5. Run TensorFlow Lite inference (Story 1.3 InferenceEngine)
6. Parse results and generate recommendations
7. Save metadata and results to SQLite
8. Total time budget: 5 seconds from capture to result display

**Upload Queue Prioritization**
```javascript
// Queue prioritization logic
// 1. Most recent images first (latest timestamp)
// 2. Failed uploads with fewer retry attempts
// 3. Images with higher confidence scores (critical diseases first)

SELECT * FROM images
WHERE sync_status IN ('pending', 'failed')
ORDER BY
  CASE WHEN sync_status = 'failed' AND upload_attempts < 3 THEN 0 ELSE 1 END,
  timestamp DESC
LIMIT 50;
```

**S3 Upload Process**
1. Request pre-signed upload URL from backend API
2. Upload image file to S3 using pre-signed URL
3. Backend validates upload and returns final S3 URL
4. Update local record with remote_url and sync_status='synced'
5. Optionally delete local file to free storage (keep thumbnail)
6. Sync metadata to backend PostgreSQL database

**Storage Cleanup Strategy**
- Maximum 50 images in queue (AC6 requirement)
- When 51st image captured:
  - Find oldest synced image (sync_status='synced', oldest timestamp)
  - Delete local file
  - Keep database record with remote_url for reference
- Never delete images with sync_status='pending' or 'failed'
- User can manually clear upload queue from settings

### Security Considerations

[Source: architecture/architectural-principles-and-best-practices.md]
- **Pre-Signed URLs**: Use temporary pre-signed URLs for S3 uploads (expire in 15 minutes)
- **HTTPS**: All uploads over encrypted connection
- **GPS Privacy**: User can opt-out of location tracking in settings
- **JWT Auth**: Backend API requires authentication for pre-signed URL requests
- **GDPR Compliance**: User can delete images with "Right to be forgotten"

### Performance Requirements

[Source: architecture/non-functional-specifications.md]
- **Processing Time**: On-device analysis must complete in <5 seconds (AC2)
- **Upload Speed**: Optimize for 2G/3G networks (compress images)
- **Queue Processing**: Upload 10 images in parallel when WiFi available
- **Background Upload**: Continue uploads in background (iOS/Android background tasks)

**Optimization Strategies**:
- Compress images to 80% quality (~2-3MB per image)
- Use delta sync: only upload new/changed images
- Batch metadata updates to backend (reduce API calls)
- Implement upload pause/resume for interrupted connections
