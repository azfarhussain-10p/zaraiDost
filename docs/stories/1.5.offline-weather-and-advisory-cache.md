# Story 1.5: Offline Weather and Advisory Cache

## Status
Draft

## Story
**As a** farmer planning my weekly work,
**I want** recent weather forecasts and advisories cached locally,
**so that** I can reference them even when offline.

## Acceptance Criteria
1. AC1: Last 7 days of weather data cached locally
2. AC2: Last received advisories (irrigation, market, climate) cached
3. AC3: Cache refreshes automatically when online
4. AC4: Stale data clearly marked with last-updated timestamp
5. AC5: User can view cached vs live data indicator
6. AC6: Cache size limited to 10MB

**Cache Refresh Strategy**
- **Automatic Refresh Triggers**:
  1. Network connectivity restored (from NetworkMonitor)
  2. Periodic refresh every 6 hours when online
  3. User opens weather/advisory screen after cache expired
  4. Manual refresh via pull-to-refresh gesture
- **Refresh Priority Order**:
  1. Weather forecast (most critical for daily planning)
  2. Climate alerts (urgent notifications)
  3. Market prices (time-sensitive)
  4. Irrigation advisories (less time-sensitive)
- **Differential Updates**:
  - Send last_updated timestamp to backend
  - Backend returns only new/changed data since timestamp
  - Reduces bandwidth usage on slow connections

**Cache Staleness Classification**

**Cache Size Management**
- Total cache budget: 10MB (AC6)
- Estimated breakdown:
  - Weather data (7 days × 2 locations): ~2MB
  - Advisories (5 per type × 3 types): ~5MB
  - Metadata and indexes: ~1MB
  - Reserve: ~2MB
- Cleanup priorities when approaching limit:
  1. Delete weather data older than 7 days
  2. Delete low-priority advisories (priority='low')
  3. Delete archived market advisories (>30 days old)
  4. Reduce advisory retention from 5 to 3 per type

### Data Model Requirements

**Weather Cache Table**
```sql
CREATE TABLE weather_cache (
  id TEXT PRIMARY KEY,
  location_id TEXT NOT NULL,
  forecast_date DATE NOT NULL,
  temperature_high_c REAL,
  temperature_low_c REAL,
  humidity_percent INTEGER,
  rainfall_mm REAL,
  wind_speed_kmh REAL,
  wind_direction TEXT,
  weather_condition TEXT,
  uv_index INTEGER,
  sunrise TEXT,
  sunset TEXT,
  forecast_type TEXT DEFAULT 'daily',
  data_source TEXT,
  last_updated DATETIME NOT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(location_id, forecast_date, forecast_type)
);

CREATE INDEX idx_weather_location_date ON weather_cache(location_id, forecast_date DESC);
CREATE INDEX idx_weather_last_updated ON weather_cache(last_updated);
```

**Advisories Cache Table**
```sql
CREATE TABLE advisories_cache (
  id TEXT PRIMARY KEY,
  advisory_type TEXT NOT NULL,        -- 'irrigation', 'market', 'climate'
  title TEXT NOT NULL,
  content TEXT NOT NULL,
  priority TEXT DEFAULT 'normal',     -- 'critical', 'high', 'normal', 'low'
  applicable_crops TEXT,              -- JSON array
  location_scope TEXT,
  valid_from DATE,
  valid_until DATE,
  is_critical BOOLEAN DEFAULT 0,
  data_source TEXT,
  last_updated DATETIME NOT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_advisory_type_date ON advisories_cache(advisory_type, valid_until DESC);
CREATE INDEX idx_advisory_priority ON advisories_cache(priority, is_critical);
CREATE INDEX idx_advisory_last_updated ON advisories_cache(last_updated);
```

**Cache Metadata Table**
```sql
CREATE TABLE cache_metadata (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  cache_type TEXT NOT NULL,           -- 'weather', 'advisory'
  location_id TEXT,
  last_refresh_attempt DATETIME,
  last_refresh_success DATETIME,
  next_refresh_scheduled DATETIME,
  refresh_error_message TEXT,
  total_size_bytes INTEGER DEFAULT 0,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(cache_type, location_id)
);
```

### Security Considerations

[Source: architecture/architectural-principles-and-best-practices.md]
- **JWT Authentication**: Backend API requires authentication for weather/advisory requests
- **HTTPS/TLS**: All data fetched over encrypted connection
- **Data Privacy**: Location-based weather data doesn't expose exact GPS coordinates
- **GDPR Compliance**: User can clear cache and delete weather history

### Performance Requirements

[Source: architecture/non-functional-specifications.md]
- **Cache Access Time**: <500ms for retrieving cached weather/advisories
- **Refresh Time**: Complete cache refresh in <30 seconds on 3G
- **Storage Efficiency**: Compress JSON data to minimize cache size
- **Background Refresh**: Use background fetch to refresh cache without blocking UI

**Optimization Strategies**:
- Compress advisory content using gzip before storing
- Use database indexes for fast date-range queries
- Lazy load advisory details (only fetch full content when opened)
- Batch API requests (fetch all cache data in single GraphQL query)
