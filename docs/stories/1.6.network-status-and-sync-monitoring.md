## Story
**As a** farmer using the app,
**I want** to see my connection status and sync state,
**so that** I know when data is backed up and when I'm working offline.

6. AC6: Option to restrict sync to WiFi only

**Pending Changes Counter Logic**
```sql
-- Count all pending changes across entities
SELECT
  'farmers' as entity_type,
  COUNT(*) as pending_count
FROM farmers
WHERE sync_status IN ('pending', 'failed')
UNION ALL
SELECT 'fields', COUNT(*) FROM fields WHERE sync_status IN ('pending', 'failed')
UNION ALL
SELECT 'crops', COUNT(*) FROM crops WHERE sync_status IN ('pending', 'failed')
UNION ALL
SELECT 'queries', COUNT(*) FROM queries WHERE sync_status IN ('pending', 'failed')
UNION ALL
SELECT 'images', COUNT(*) FROM images WHERE sync_status IN ('pending', 'failed');

-- Total pending changes
SELECT SUM(pending_count) as total FROM (/* above query */);
```

**WiFi-Only Sync Logic**
```javascript
// Sync decision tree
function canPerformSync(trigger, userSettings, connectionType) {
  // Manual sync always allowed (with confirmation on cellular)
  if (trigger === 'manual') {
    if (connectionType === 'cellular' && userSettings.wifiOnly) {
      return 'confirm_required';  // Show warning dialog
    }
    return true;
  }

  // Automatic sync respects WiFi-only setting
  if (trigger === 'automatic' || trigger === 'background') {
    if (userSettings.wifiOnly && connectionType !== 'wifi') {
      return false;  // Block sync on cellular
    }
    return true;
  }

  return false;
}
```

### Data Model Requirements

**Sync History Table**
```sql
CREATE TABLE sync_history (
  id TEXT PRIMARY KEY,
  sync_start_time DATETIME NOT NULL,
  sync_end_time DATETIME,
  sync_duration_ms INTEGER,
  sync_status TEXT NOT NULL,        -- 'success', 'failed', 'partial'
  connection_type TEXT,              -- 'wifi', 'cellular', 'unknown'
  entities_synced TEXT,              -- JSON object
  total_records_synced INTEGER DEFAULT 0,
  total_records_failed INTEGER DEFAULT 0,
  data_uploaded_bytes INTEGER DEFAULT 0,
  data_downloaded_bytes INTEGER DEFAULT 0,
  error_messages TEXT,               -- JSON array
  sync_trigger TEXT,                 -- 'automatic', 'manual', 'connectivity_restored'
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_sync_history_date ON sync_history(sync_start_time DESC);
CREATE INDEX idx_sync_history_status ON sync_history(sync_status);
```

**Data Usage Table**
```sql
CREATE TABLE data_usage (
  id TEXT PRIMARY KEY,
  date DATE NOT NULL,
  connection_type TEXT NOT NULL,     -- 'wifi', 'cellular'
  sync_operation_id TEXT,
  bytes_uploaded INTEGER DEFAULT 0,
  bytes_downloaded INTEGER DEFAULT 0,
  total_bytes INTEGER DEFAULT 0,
  entity_breakdown TEXT,             -- JSON object
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (sync_operation_id) REFERENCES sync_history(id)
);

CREATE INDEX idx_data_usage_date ON data_usage(date DESC);
CREATE INDEX idx_data_usage_connection ON data_usage(connection_type);
```

**Sync Preferences Table**
```sql
CREATE TABLE sync_preferences (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id TEXT,
  wifi_only_mode BOOLEAN DEFAULT 0,
  background_sync_enabled BOOLEAN DEFAULT 1,
  sync_frequency_hours INTEGER DEFAULT 6,  -- 6, 12, 24, or -1 for manual only
  auto_image_upload BOOLEAN DEFAULT 1,
  low_battery_skip_sync BOOLEAN DEFAULT 1,  -- Skip sync if battery <20%
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

**Sync State Metadata Table**
```sql
CREATE TABLE sync_state_metadata (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  last_successful_sync DATETIME,
  last_sync_attempt DATETIME,
  last_sync_duration_ms INTEGER,
  next_scheduled_sync DATETIME,
  sync_enabled BOOLEAN DEFAULT 1,
  current_status TEXT DEFAULT 'idle',  -- 'idle', 'syncing', 'synced', 'failed'
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

### UI/UX Design Specifications

**Network Status Indicator**
- Location: Top-right corner of app header (persistent across all screens)
- Size: Small icon (24px) with optional text label
- Colors: Green (WiFi/good), Yellow (3G), Orange (2G), Red (offline)
- Interaction: Tap to view detailed connection info and sync status

**Pending Changes Counter**
- Location: Badge on sync icon or dedicated button in header
- Display: Number badge (e.g., "12") or simplified (e.g., "9+")
- Color: Orange/yellow to draw attention
- Interaction: Tap to navigate to SyncStatusDashboard

**Last Sync Timestamp**
- Format: Human-readable relative time (e.g., "Synced 2 hours ago")
- Location: Sync status dashboard, settings screen
- Update: Refresh every minute when screen visible

**Sync Progress Indicator**
- Type: Linear progress bar during active sync
- Display: Percentage and current entity (e.g., "Syncing images... 60%")
- Location: Bottom sheet or inline on sync dashboard

### Performance Requirements

[Source: architecture/non-functional-specifications.md]
- **UI Responsiveness**: Network status updates without lag (<100ms)
- **Counter Updates**: Pending changes counter updates in real-time
- **History Query**: Sync history retrieval <500ms for 30 entries
- **Statistics Calculation**: Data usage stats compute in <1 second

**Optimization Strategies**:
- Cache pending changes count (recalculate only on data change)
- Use database triggers to update counters automatically
- Lazy load sync history (paginate, load 10 entries at a time)
- Compress old sync history entries (aggregate by day after 7 days)
