# Story 1.3: Offline AI Model Storage

## Status
Approve

## Story
**As a** farmer working offline,
**I want** AI models to run on my device without internet,
**so that** I can get crop health analysis and recommendations anywhere.

## Acceptance Criteria
1. AC1: TensorFlow Lite models downloaded during initial setup or WiFi connection
2. AC2: Models compressed to fit within 100MB app size limit
3. AC3: On-device inference works without network calls
4. AC4: Model version tracking for future updates
5. AC5: Fallback to cached results if model loading fails

### Technical Implementation Details

**TensorFlow Lite Integration**
- Use `@tensorflow/tfjs-react-native` or `react-native-tensorflow-lite`
- Model format: `.tflite` (converted from TensorFlow SavedModel or PyTorch)
- Model compression techniques: Quantization (INT8), pruning
- Target model size: <50MB for disease detection model

**Disease Detection Model Requirements**
[Source: prd/epic-3-crop-health-monitoring.md]
- Recognizes 50+ diseases, pests, and nutrient deficiencies
- Covers Pakistani crops: wheat, rice, cotton, sugarcane, corn
- Input: 224x224 RGB images (standard MobileNet input size)
- Output: Class probabilities for 50+ categories + confidence scores

**Model Storage Location**
- iOS: `DocumentDirectory` or `LibraryDirectory`
- Android: `FilesDir` (internal storage, private to app)
- Path example: `{APP_DATA}/models/disease_detection_v1.2.tflite`

**Model Versioning Schema**
```sql
CREATE TABLE model_metadata (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  model_name TEXT NOT NULL,              -- 'disease_detection'
  version TEXT NOT NULL,                 -- 'v1.2'
  file_path TEXT NOT NULL,
  file_size_bytes INTEGER,
  checksum TEXT,                         -- SHA256 hash
  download_date DATETIME,
  is_active BOOLEAN DEFAULT 0,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

**Inference Cache Schema**
```sql
CREATE TABLE inference_cache (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  image_hash TEXT NOT NULL,              -- Perceptual hash of image
  model_version TEXT NOT NULL,
  prediction_result TEXT NOT NULL,       -- JSON: {class, confidence, top_5}
  inference_time_ms INTEGER,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(image_hash, model_version)
);
CREATE INDEX idx_image_hash ON inference_cache(image_hash);
```

**Model Download Process**
1. Check current model version in local database
2. Query backend API for latest model version
3. If update available, prompt user to download
4. Download model file with progress tracking
5. Verify checksum after download
6. Save model to file system and update metadata
7. Set new model as active, archive old version

**Image Preprocessing Pipeline**
```javascript
// Pseudocode
1. Load image from file system
2. Resize to 224x224 (model input size)
3. Normalize pixel values [0, 255] → [0, 1] or [-1, 1] depending on model
4. Convert to tensor format
5. Add batch dimension: [1, 224, 224, 3]
```

**Inference Output Parsing**
```javascript
// Model output: [batch, num_classes] = [1, 50+]
// Parse top 5 predictions:
{
  predictions: [
    { class: "Wheat Leaf Rust", confidence: 0.89 },
    { class: "Wheat Yellow Rust", confidence: 0.06 },
    ...
  ],
  inference_time_ms: 3200
}
```

### Storage Management Strategy

[Source: prd/epic-1-offline-first-intelligence.md]
- Total app storage limit: <100MB
- Disease detection model target: <50MB
- Inference cache limit: 1000 predictions (~5MB)
- Automatic cleanup: delete oldest cached predictions when limit reached
- Model updates: delete old version after successful new version verification

### Performance Requirements

[Source: architecture/non-functional-specifications.md]
- **Inference Time**: <5 seconds per image (AC from Epic 3, Story 3.2)
- **Model Load Time**: <3 seconds on app startup
- **Memory Usage**: Monitor model memory footprint (target <200MB RAM)

**Optimization Techniques**:
- Model quantization: FP32 → INT8 (reduces size by 4x)
- Use GPU delegate on compatible devices for faster inference
- Lazy loading: load model only when needed (first image capture)

### Security Considerations

[Source: architecture/architectural-principles-and-best-practices.md]
- **Model Integrity**: Verify checksum to prevent tampering
- **HTTPS**: Download models over encrypted connection
- **Model Versioning**: Prevent downgrade attacks (only allow newer versions)

### Error Handling & Fallback

**Model Loading Failures**:
1. Attempt to reload model (retry once)
2. If persistent failure, check for cached results for similar image
3. If no cache, notify user model unavailable, suggest re-download
4. Log error for monitoring

**Inference Failures**:
1. Retry inference once
2. Fall back to cached result if available
3. Suggest cloud analysis if online
4. Provide generic crop health tips as last resort
